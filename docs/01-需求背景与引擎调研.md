# 01. 需求背景与搜索引擎横向调研

## 一、 需求起源与原始痛点

在构建面向大语言模型（LLM）的智能检索工具（MCP）时，初始版本采用了主流的三大商业 AI 搜索服务：
1. **Exa.ai**：神经语义搜索，擅长高质量技术文档、论文和学术资料；
2. **Tavily**：专为 Agent 定制，自带结构化 AI 总结与正文片段；
3. **Brave Search**：独立索引库，擅长时事热点与通用客观事实检索。

### 原始架构的缺陷：
- **额度硬顶（HTTP 429）**：商业服务免费额度通常在每月 1000~2000 次之间。一旦月底配额消耗殆尽，服务直接抛出 429 异常，整个 MCP 瘫痪。
- **无容错断联**：在初版中，只要配置的商业引擎均无法响应，LLM 搜索调用即彻底中断，导致对话中断。
- **缺乏免 Key 保底**：缺少无需任何 API 密钥、零成本、无调用上限的终极兜底方案。

---

## 二、 免 Key 免费搜索引擎实测与横向对比

为了打造“永不断联”的终极保底方案，我们在本地开发环境（Windows 11 / Node.js 24 / 国内宽带环境）对几大主流免 Key 方案进行了真实连通性与数据抽取测试：

| 方案 / 引擎 | 是否需 Key | 国内直连实测结果 | 爬取难度与反爬策略 | 落地页与数据质量 | 综合评分与结论 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **微软必应 (Bing 国内版)** | ❌ 完全免 Key | **✅ 极佳** (平均延迟 200~400ms，毫秒级响应) | **极温和**：标准浏览器 User-Agent 即可，无滑动验证码，HTML 结构规范 (`.b_algo`) | **优秀**：直接提供真实落地页原始 URL，正文摘要清晰 | 🥇 **终极保底首选** |
| **DuckDuckGo (DDG HTML)** | ❌ 完全免 Key | **❌ 超时阻断** (国内直连 100% 出现 SNI 阻断超时) | **温和**：支持轻量 HTML 表单提交，无验证码 | **优良**：英文结果质量高，URL 需从 `uddg=` 参数反解 | 🥈 **代理/海外第一梯队** (需设置短超时快速让位) |
| **SearXNG 公共实例池** | ❌ 完全免 Key | ⚠️ 极不稳定 (公开实例超 80% 无法直连或关闭 JSON) | **苛刻**：公共节点频繁触发 Rate Limit 或 Cloudflare 5秒盾 | **参差不齐**：聚合多源但经常解析失败 | 🥉 **不建议公开实例** (自建 Docker 除外) |
| **百度搜索 (Baidu)** | ❌ 完全免 Key | **✅ 极佳** (直连 200) | **较严**：高频抓取易弹滑块验证码 | **较差**：落地页全是加密重定向链接 (`baidu.com/link?url=...`)，大模型无法直接利用 | ⚠️ **体验欠佳，不作推荐** |
| **搜狗 / 360 搜索** | ❌ 完全免 Key | **✅ 良好** (直连 200) | 一般 | 结果偏商业化与本土资讯，技术/开源/代码类召回率偏低 | ⚠️ **仅备用** |

---

## 三、 选型定案与设计决策

根据上述实测数据，我们制定了免 Key 兜底层的技术标准：
1. **优先 DuckDuckGo**：
   - 兼顾海外环境、代理网络及极客用户的无痕隐私习惯；
   - **关键设计约束**：将请求超时压缩至 **4.5 秒**。如果处于中国大陆且无代理，系统在 4.5s 内立即主动熔断，避免用户长时间卡顿，迅速让位给必应。
2. **终极保底 微软必应 (Bing)**：
   - 依赖微软国内 CDN 节点，提供绝对可靠的连通率；
   - 纯正则提取 HTML 节点，无须启动庞大的无头浏览器（Puppeteer/Playwright），内存零负担，极速返回纯净的标题、真实 URL 与摘要。
