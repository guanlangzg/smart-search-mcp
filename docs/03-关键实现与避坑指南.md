# 03. 关键实现与避坑指南

## 一、 Node.js 与 MCP 协议避坑关键

### 1. stdio 传输通道与日志隔离
- **踩坑现象**：在 MCP 服务代码中使用 `console.log("正在搜索...")` 会直接导致客户端报 JSON 解析崩溃 `SyntaxError: Unexpected token`。
- **根因分析**：MCP 标准的 Stdio 传输使用标准输出 (`stdout`) 传输 JSON-RPC 2.0 数据帧。任何随意的文本输出都会污染协议帧流。
- **最佳实践**：
  - 所有调试、日志记录必须使用 `console.error(...)` 写入标准错误流 (`stderr`)；
  - 只有 MCP SDK 的 `transport` 才有权写入 `stdout`。

### 2. 现代超时控制：`AbortSignal.timeout(ms)`
在 Node.js 18+ 环境中，不再需要手写冗长的 `AbortController` 和 `setTimeout` 清理代码：
```javascript
const res = await fetch(url, {
  headers: { ... },
  signal: AbortSignal.timeout(4500), // 毫秒级自动超时中止
});
```

## 二、 网页爬虫与 HTML 文本解析技巧

为了让 MCP 保持轻量（避免引入几百兆的 Chromium 或 JSDOM），免 Key 模块全部采用轻量原生正则与文本解析：

### 1. HTML 实体字符全面反转义
搜索引擎返回的摘要中大量充斥着 HTML 实体，大模型阅读时若保留原生编码体验极差：
```javascript
function decodeHtmlEntities(str) {
  if (!str) return "";
  return str
    .replace(/&#(\d+);/g, (_, dec) => String.fromCharCode(dec))
    .replace(/&#x([0-9a-fA-F]+);/g, (_, hex) => String.fromCharCode(parseInt(hex, 16)))
    .replace(/&amp;/g, "&")
    .replace(/&lt;/g, "<")
    .replace(/&gt;/g, ">")
    .replace(/&quot;/g, '"')
    .replace(/&#39;/g, "'")
    .replace(/&ensp;/g, " ")
    .replace(/&emsp;/g, " ")
    .replace(/&middot;/g, "·")
    .replace(/&nbsp;/g, " ");
}
```

### 2. DuckDuckGo 重定向解包（还原真实落地 URL）
DuckDuckGo 的 HTML 版链接往往经过了一层包装：
`https://duckduckgo.com/l/?uddg=https%3A%2F%2Fnodejs.org%2F...`
如果直接将该链接返回给大模型，模型无法获取清晰的域名和路径，二次 fetch 也会增加延迟。
**解法**：
```javascript
let targetUrl = rawHref;
try {
  const u = new URL(targetUrl, "https://duckduckgo.com");
  const real = u.searchParams.get("uddg");
  if (real) targetUrl = decodeURIComponent(real); // 还原为 https://nodejs.org/...
} catch {}
```

### 3. Bing `.b_algo` 模块提取技巧
必应的搜索结果由多个 `<li class="b_algo">` 构成。
提取时先通过正则切块，再在每个块内单独提取 `<h2><a href="...">` 和 `<div class="b_caption">`，可以有效防止跨节点的大范围贪婪正则回溯。
